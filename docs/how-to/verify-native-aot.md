# Verify Native AOT consumers

Use .NET SDK **10.0.403**, Python 3.12 or newer and the host's native compiler:
Xcode Command Line Tools on macOS, Visual Studio's Desktop development with C++
workload on Windows, or Clang and zlib development headers on Linux.

```sh
just aot-publish
```

The equivalent is `python3 dev/prepare-aot.py`; use `python` on Windows. An optional
argument selects the expected host RID: `linux-x64`, `linux-arm64`, `win-x64` or
`osx-arm64`. A mismatched host fails before publication. The command prints its
`artifacts/aot/run.*/native.json` path.

The command packs and inspects a unique local core candidate, then publishes two
independent executables against it. `ZkLink.AotAnalysis` roots the core for full
implementation analysis. `ZkLink.AotSmoke` calls representative public APIs without
broad roots or source-project references. Both use fresh package caches and source
mapping: ZkLink resolves only from the candidate feed, while SDK compiler/runtime
packages resolve from nuget.org. Generated dependency locks are restored again in
locked mode. Core trim/AOT analyzers and publish warnings remain enabled.

Evidence includes candidate/compiler-input hashes, native file format and
architecture, executable hashes, source inputs, SDK/host information, dependency
assets, locks and publish logs. Native outputs retain project and .NET runtime
licenses/notices. The command directly runs the rooted executable and smoke
identity probe, and rejects launching the intermediate managed DLL. The smoke
checks its running process image hash, RID and disabled dynamic-code capabilities.

## Run native operations against disposable servers

Docker with Compose and OpenSSL are also required for the owned live fixtures:

```sh
just aot-check
```

This publishes a fresh candidate and directly runs it on every node of isolated
three-node ZooKeeper **3.8.7** and **3.9.6** ensembles, in TLS and mTLS modes:
twelve native live cases. To reuse a candidate whose recorded inputs are unchanged:

```sh
bash dev/test-native-aot.sh artifacts/aot/run.EXAMPLE/native.json
```

Each case checks CRUD, transactions, auxiliary queries, one-shot/persistent/
recursive watches, digest authorization and ACL identity separation. mTLS also
checks denial for a different client certificate. An existing opaque loopback
tunnel cuts and pauses the connection. Native assertions cover disconnected
request rejection, cancelled readiness waits, same-session recovery, protected
reads after digest replay, persistent/recursive gaps and later delivery, one-shot
invalidation, explicit removal, pre-send cancellation, acknowledged close and
server-observed ephemeral deletion. The tunnel does not inspect TLS records or
replay application writes.

The first node of each fixture also checks wrong server names, unknown roots,
expired certificates and TLS directed at a plaintext port. mTLS additionally
rejects a missing client certificate. These require a TLS failure rather than
accepting any connection error. The disposable PKI uses custom roots and explicit
revocation `NoCheck`; production defaults remain unchanged.

Each case has a 90-second application deadline and an outer 120-second process
guard. Every server's exact version and authenticated readiness are checked.
Cleanup retains logs, performs fresh authenticated probes, removes owned servers
and volumes, and deletes private PKI on success or failure. Keys and store
passwords remain outside retained artifacts; public evidence is scanned for leaks.

## Use externally managed disposable fixtures

On a target host without Docker, publish locally and set:

| Variable | Value |
| --- | --- |
| `ZKLINK_AOT_ENDPOINT` | One reachable secure endpoint |
| `ZKLINK_AOT_SERVER_VERSION` | Independently verified `3.8.7` or `3.9.6` |
| `ZKLINK_AOT_SECURITY_MODE` | `tls` or `mtls` |
| `ZKLINK_AOT_CERTIFICATE_DIRECTORY` | Private directory generated by the repository certificate script |
| `ZKLINK_USER`, `ZKLINK_PASSWORD` | Fresh disposable digest credentials |

Run `python dev/run-native-smoke.py <native.json>`. It verifies unchanged inputs
and executable identity before direct execution. With `--security-negatives`, also
set `ZKLINK_AOT_EXPIRED_ENDPOINT` and `ZKLINK_AOT_PLAINTEXT_ENDPOINT`. The external
fixture owner must verify server versions, protect PKI and handle server teardown.
`--native-check` only checks executable identity and makes no live operation claim.

## Evidence and remaining qualification

Inspect `native.json`, `package.json`, publish/direct-execution logs, per-server
`*-native.txt`, cleanup/readiness logs and `live-result.txt`. A matrix passes only
after all twelve native cases and cleanup complete.

The [Native AOT workflow](../../.github/workflows/native-aot.yml) defines publish,
rooted execution and smoke identity checks on all four RIDs, with separate Linux
x64/arm64 live jobs. Windows/macOS live CI fixtures remain open. Configuration
does not establish remote execution evidence.

Local macOS arm64 execution is the initial verification target. Four-RID live
qualification, sent-request cancellation/unknown outcomes, broader secure
recovery, revocation/rotation and optional DI qualification remain open. Core
`IsAotCompatible` metadata stays disabled; these checks do not declare release
support.
